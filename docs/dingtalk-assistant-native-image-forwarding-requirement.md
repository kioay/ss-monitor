# 钉钉助手支持子 Agent 图片附件原生转发

## 基本信息

- 优先级：P0
- 责任模块：`dingtalk-assistant-agent`
- 当前所有者：`lx@wooduan.com`
- 影响范围：钉钉助手调用会生成图片附件的子 Agent

## 背景

钉钉助手调用子 Agent 后，目前只转发文本结果。即使子 Agent 已成功生成并上传有效的 JPEG 或 PNG 图片附件，钉钉助手仍会将图片转换为下载链接，用户必须点击链接才能查看。

受控测试已经排除图片数量问题：子 Agent 仅返回 4 张有效 JPEG 时，钉钉助手仍未发送原生图片消息。测试中子任务成功上传了 4 个 `image/jpeg` 产物，父任务日志只有文本回复写入记录，没有下载附件、上传钉钉媒体或发送图片消息的记录。

## 目标

当子 Agent 返回图片附件时，钉钉助手应将图片直接发送到原钉钉会话，让用户无需点击链接即可查看，同时保留文本报告和素材来源链接。

## 功能要求

1. 钉钉助手等待子 Agent 完成后，读取子任务返回的 `artifactFiles`。
2. 筛选 `contentType` 以 `image/` 开头的附件。
3. 如果调用结果中没有完整附件信息，通过子任务 `taskRunId` 查询 Center 任务产物。
4. 通过 Center 鉴权接口下载图片字节，不在消息或日志中暴露 OSS 签名地址。
5. 使用平台注入的 DWS 登录态上传图片，获得钉钉可用的媒体标识。
6. 通过 DWS 向原 `replyTarget` 发送钉钉原生图片消息。
7. 每张图片作为独立消息发送，并保持子 Agent 返回顺序。
8. 单次最多发送前 4 张图片，避免消息刷屏；其余图片保留在 Agent 详情页。
9. 主报告文本继续正常发送，图片消息不能替代报告。
10. 只有拥有 `channelReplyAuthority` 的父 Agent 可以发送图片，子 Agent 不得绕过父 Agent 直接回复钉钉。

## 建议处理流程

```text
等待子 Agent 完成
  -> 获取 child taskRunId
  -> 读取 artifactFiles 或查询任务产物
  -> 筛选前 4 个 image/* 附件
  -> 通过 Center 鉴权接口下载图片
  -> 使用 DWS 上传钉钉媒体
  -> 向原 replyTarget 逐张发送图片消息
  -> 发送文本报告
  -> 失败附件降级为链接
```

## 失败处理

- 单张图片上传失败时，继续发送其他图片。
- 图片全部发送失败时，才降级为可点击的附件链接。
- 没有图片附件时，只发送文本，不显示“图片已生成”。
- 子任务重试或父任务重放时，应避免重复发送同一 `artifactId`。
- 不支持的图片格式应转换为 DWS 支持的 JPEG 或 PNG；无法转换时执行链接降级。
- DWS 上传或发送超时应记录明确原因，不得导致文本报告丢失。

## 安全要求

- 不得在钉钉消息、任务结果、产物或日志中输出 OSS 签名 URL。
- 不得记录 DWS 登录凭证、访问令牌、Cookie 或私有请求头。
- 图片下载必须使用 Center 提供的授权链路。
- 必须使用父任务已有的 `replyTarget`，不得根据文本内容推测会话目标。

## 日志要求

日志应记录以下信息：

- 子任务 `taskRunId`
- 找到的图片附件数量
- 每张图片的 `artifactId`、格式和大小
- DWS 媒体上传是否成功
- 原生图片消息发送是否成功
- 是否发生链接降级及失败原因

日志不得记录签名 URL、令牌和会话凭证。

## 验收标准

1. `竞品素材侦查` 返回 4 张 JPEG 时，钉钉直接收到 4 条可见图片消息。
2. 用户无需点击任何链接即可查看图片。
3. 文本报告、竞品名称和素材来源链接仍正常显示。
4. 子 Agent 返回 24 张图片时，只发送前 4 张，其余图片不在钉钉刷屏。
5. 某一张图片发送失败时，其他图片仍能正常发送。
6. 图片全部发送失败时才显示附件链接。
7. 钉钉消息和任务日志中不出现 OSS 签名地址。
8. 同一父任务重试时不会重复发送已经成功发送的图片。
9. 没有图片附件的子任务保持原有纯文本回复行为。
10. 钉钉助手调用其他纯文本子 Agent 的行为不受影响。

## 测试用例

| 场景 | 子 Agent 产物 | 预期结果 |
| --- | --- | --- |
| 正常四图 | 4 个有效 `image/jpeg` | 4 条原生图片消息和 1 条文本报告 |
| 超过上限 | 24 个有效图片附件 | 只发送前 4 张，文本报告正常 |
| 部分失败 | 4 张图片中 1 张上传失败 | 其余 3 张正常发送，失败项降级 |
| 全部失败 | 4 张图片全部上传失败 | 文本报告正常，图片使用链接兜底 |
| 无图片 | 只有 Markdown/JSON 产物 | 只发送文本，不显示图片提示 |
| 父任务重试 | 相同 `artifactId` 再次出现 | 不重复发送已成功图片 |

## 改动边界

本需求只修改 `dingtalk-assistant-agent` 的子 Agent 结果转发逻辑。

- 不修改 `design-inspiration` 的素材生成与附件上传逻辑。
- 不让业务子 Agent 直接调用 DWS 回复钉钉。
- 不使用 `sdk-showcase-agent` 作为转发中间层；该 Agent 当前只演示钉钉文档创建和子 Agent 文本调度，不包含聊天图片转发能力。
